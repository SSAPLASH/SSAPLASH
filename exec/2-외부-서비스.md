# 2. 외부 서비스

프로젝트가 쓰는 외부 서비스의 가입·활용 정보다. 키와 비밀번호는 적지 않고, 발급 위치와 넣을 변수만 적는다.

## 2.1 요약

| 서비스 | 용도 | 가입·발급 | 넣는 곳 |
| --- | --- | --- | --- |
| Google OAuth 2.0 | 소셜 로그인 | Google Cloud 콘솔 | `GOOGLE_CLIENT_ID`, `GOOGLE_CLIENT_SECRET` |
| SSAFY OAuth | 소셜 로그인 | SSAFY 프로젝트 OAuth 신청 | `SSAFY_CLIENT_ID`, `SSAFY_CLIENT_SECRET` |
| Let's Encrypt | HTTPS 인증서 | 가입 없음(certbot 발급 때 이메일 입력) | 서버 `infra_letsencrypt` 볼륨 |
| GitLab (lab.ssafy.com) | 소스 저장소, CI/CD 러너 | SSAFY 계정 | 러너 토큰은 서버에서만 입력 |
| Hugging Face | AI 모델 가중치 내려받기 | 가입 없이 공개 모델 내려받기 | GPU 서버 캐시 |
| Ollama | LLM 실행과 모델 내려받기 | 가입 없음 | GPU 서버 `~/ollama-models` |
| PyTorch 휠 저장소 | CUDA 12.8용 torch 설치 | 가입 없음 | GPU 서버 `.venv` |

결제가 필요한 외부 유료 API(LLM API 등)는 쓰지 않는다. LLM은 GPU 서버의 Ollama에서 직접 돌린다.

## 2.2 소셜 로그인

로그인 흐름: 브라우저 → `GET /api/auth/{google|ssafy}/login` → 제공자 동의 화면 → `GET /api/auth/{google|ssafy}/callback` → 서비스 화면(`/auth/callback`).
제공자 설정(인가·토큰·사용자 정보 주소, scope)은 `BE/src/main/resources/application.yaml`의 `auth.providers`에 있다.

### Google

1. [Google Cloud 콘솔](https://console.cloud.google.com/)에서 프로젝트를 만든다.
2. "API 및 서비스 → OAuth 동의 화면"을 설정한다. 게시 상태가 "테스트"면 로그인할 계정을 테스트 사용자로 추가한다.
3. "사용자 인증 정보 → OAuth 클라이언트 ID"를 만든다(애플리케이션 유형: 웹 애플리케이션).
4. 승인된 리디렉션 URI에 아래 주소를 등록한다. `OAUTH_REDIRECT_BASE_URL` 뒤에 경로를 붙인 값과 글자까지 같아야 한다.
   - 운영: `https://k15a307.p.ssafy.io/api/auth/google/callback`
   - 로컬: `http://localhost:8080/api/auth/google/callback`
5. 발급된 클라이언트 ID와 비밀번호를 서버 `.env`의 `GOOGLE_CLIENT_ID`, `GOOGLE_CLIENT_SECRET`에 넣는다.

| 항목 | 값 |
| --- | --- |
| 인가 주소 | `https://accounts.google.com/o/oauth2/v2/auth` |
| 토큰 주소 | `https://oauth2.googleapis.com/token` |
| 사용자 정보 주소 | `https://openidconnect.googleapis.com/v1/userinfo` |
| scope | `openid email profile` |

### SSAFY

1. SSAFY 프로젝트 OAuth 사용을 신청해 클라이언트 ID와 비밀번호를 받는다.
2. 리디렉션 URI로 아래 주소를 등록한다.
   - 운영: `https://k15a307.p.ssafy.io/api/auth/ssafy/callback`
   - 로컬: `http://localhost:8080/api/auth/ssafy/callback`
3. 서버 `.env`의 `SSAFY_CLIENT_ID`, `SSAFY_CLIENT_SECRET`에 넣는다.

| 항목 | 값 |
| --- | --- |
| 인가 주소 | `https://project.ssafy.com/oauth/sso-check` |
| 토큰 주소 | `https://project.ssafy.com/ssafy/oauth2/token` |
| 사용자 정보 주소 | `https://project.ssafy.com/ssafy/resources/userInfo` |
| scope | 없음(SSAFY 명세에 scope가 없음) |

- 키가 비어 있는 제공자는 비활성으로 시작한다(로그인 경로 404, 기동 로그에 WARN).
- 같은 사람이라도 Google과 SSAFY로 로그인하면 서로 다른 회원이다.
- 관리자 권한은 `ADMIN_EMAILS`에 적힌 이메일로 로그인할 때마다 다시 정한다.

## 2.3 HTTPS 인증서 (Let's Encrypt)

- 도메인 `k15a307.p.ssafy.io`는 SSAFY가 제공한다.
- `certbot` 컨테이너로 webroot 방식 발급을 한다. 발급할 때 연락용 이메일을 입력한다.
- 자동 갱신은 구성하지 않았다. 만료 30일 전부터 수동으로 갱신한다.
- 발급·갱신 명령은 [Infra/PORTING.md](../Infra/PORTING.md) 5절에 있다.

## 2.4 GitLab CI/CD

- 저장소: `https://lab.ssafy.com/s15-final/S15P31A307`
- 러너 2개를 EC2 서버에 등록한다. GitLab 프로젝트의 Settings → CI/CD → Runners → New project runner에서 만든다.

| 러너 | executor | 태그 | 용도 |
| --- | --- | --- | --- |
| `ec2-docker` | docker | — | CI(빌드·테스트) |
| `ec2-deploy` | shell | `deploy` (Protected) | `main` 배포·롤백 |

- 러너 토큰(`glrt-`)은 서버 터미널에만 입력하고 문서·채팅에 남기지 않는다.
- 등록 절차: [Infra/README.md](../Infra/README.md) CI 러너 절, [Infra/deploy/README.md](../Infra/deploy/README.md) "서버 최초 준비".

## 2.5 AI 모델 내려받기 (GPU 서버)

모두 가입 없이 공개 주소에서 내려받는다. 워커를 처음 실행할 때(`ssaplash-worker check`) 받아 캐시에 둔다.

| 모델 | 용도 | 출처 |
| --- | --- | --- |
| BS-RoFormer SW | 음원에서 드럼 분리 | Hugging Face `FractalSurfer/BS-RoFormer-SW-6stem` |
| AST (`MIT/ast-finetuned-audioset-10-10-0.4593`) | 업로드 음원이 음악인지 검사 | Hugging Face |
| Beat This! | 박 추적(BPM, 첫 마디) | 저자 공개 체크포인트(`AI/configs/chart/`의 주소) |
| STRUM 파인튜닝 가중치 | 드럼 채보 | 팀이 학습한 파일. 공개 저장소 없음(1번 문서 1.5절) |
| gemma3:12b | 연주 중 코칭 문구, 리포트 총평 | Ollama 모델 저장소(`ollama pull gemma3:12b`) |

- Gemma 모델은 Google의 Gemma 이용 약관이 적용된다(`AI/docs/coach-narrative.md` "라이선스 확인").
- 워커가 BE에 접속하지 못하면 GPU 서버의 공인 IP를 `curl -s https://api.ipify.org`로 확인해 Nginx 허용 목록과 비교한다.
