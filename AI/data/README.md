# AI/data — 벤치마크 데이터

이 폴더의 음원·결과 파일은 git이 추적하지 않는다. 이 README만 추적한다. 받는 법·md5·라이선스는 `AI/README.md`의 "데이터" 절에 있고, 여기에는 **무슨 폴더에 무슨 데이터가 있는지**만 적는다.

```
AI/data/
├─ musdb18hq/   MUSDB18-HQ. 분리 모델 평가용 150곡
├─ gmd/         Groove MIDI Dataset. 합성곡 드럼 재료
└─ synth_v1/    우리가 만든 합성곡 5곡
```

## musdb18hq/ — MUSDB18-HQ (약 52GB)

| 하위 | 크기 | 내용 |
| --- | --- | --- |
| `musdb18hq.zip` | 22GB | 받은 원본 압축. md5 확인 뒤에는 지워도 된다. 코랩에 올릴 때 압축본이 편해서 두고 있다 |
| `test/` 50곡 | 11GB | **분리 모델 평가용.** 모델에 `mixture.wav`를 넣고 나온 드럼을 `drums.wav`와 비교한다. 논문과 리더보드가 전부 이 50곡으로 점수를 내므로 우리 수치와 직접 비교할 수 있다 |
| `train/` 100곡 | 19GB | 평가에는 쓰지 않는다. 후보 모델들이 이 100곡으로 학습했기 때문이다. 합성곡의 반주 재료로만 쓴다 |

곡마다 파일 5개가 있다. `mixture.wav`(원곡), `drums.wav`, `bass.wav`, `other.wav`, `vocals.wav`. 네 트랙을 더하면 원곡이 된다. 44.1kHz 스테레오 16비트, 곡당 3~7분, 록·팝 위주. 라이선스는 교육·연구 목적 전용이라 저장소나 Notion에 음원을 올리지 않는다.

## gmd/ — Groove MIDI Dataset v1.0.0 (약 11GB)

| 하위 | 크기 | 내용 |
| --- | --- | --- |
| `groove-v1.0.0.zip` | 4.8GB | 받은 원본 압축. 지워도 된다 |
| `groove/info.csv` | — | 연주 1150개의 목록. 드러머, 스타일, bpm, 박자, 길이, train/validation/test 구분 |
| `groove/drummer1~10/session*/` | 6.2GB | 연주마다 `.mid`와 `.wav` 한 쌍 |

드러머 10명이 전자 드럼(Roland TD-11)으로 친 연주다. `.mid`는 "몇 초에 어느 드럼을 얼마나 세게 쳤는지"의 기록이고 `.wav`는 그때 난 소리라서, 둘이 2ms 안에서 맞는다. 파일명에 정보가 다 들어 있다. 예를 들어 `101_dance-disco_120_beat_4-4`는 101번 연주, 디스코, 120bpm, 비트(필인 아님), 4/4박자다. 우리는 이 중 5개만 쓴다. 라이선스는 CC BY 4.0이다.

## synth_v1/ — 합성곡 5곡 (약 216MB)

합성곡은 우리가 직접 합쳐서 만든 곡이다. 실제 밴드가 녹음한 곡이 아니라, 따로 있던 드럼 소리(GMD)와 반주 소리(MUSDB train 곡에서 드럼을 뺀 것)를 더해 만든 가짜 곡이다. 만드는 법과 레시피는 `AI/configs/bench/datasets/synth_v1_recipe.yaml`과 `AI/scripts/make_synth_songs.py`에 있다.

왜 만드냐면, 벤치마크에 "정답"이 완벽한 곡이 필요해서다.

- 분리 벤치마크의 정답은 "이 곡의 드럼만 따로 있는 소리"다. MUSDB는 트랙별로 녹음한 곡이라 이 정답이 있다.
- 그런데 "드럼을 정확히 몇 초에 쳤는가"는 MUSDB에 없다. 사람이 친 소리를 녹음만 했지 타격 시각을 기록하지는 않았다.
- GMD는 전자 드럼으로 쳐서 MIDI가 남아 있다. 타격 시각이 2ms 안에서 정확하다. 대신 드럼만 있고 반주가 없다.

그래서 GMD 드럼 + MUSDB 반주를 더하면 드럼 정답과 타격 시각 정답을 둘 다 가진 곡이 된다. 섞기 전 원본을 우리가 들고 있으니 정답이 확실하다. 이 곡으로 "분리 모델을 거친 뒤에도 타격이 제자리에 살아 있는가"를 재고, 나중에 채보 모델 벤치마크에서도 "타격을 얼마나 맞게 받아 적었는가"의 정답으로 쓴다. 단점은 드럼과 반주가 같이 연주된 게 아니라서 음악적으로 어색할 수 있다는 것이다. 실제 곡 느낌의 평가는 MUSDB 50곡이 맡고, 합성곡 5곡은 정밀 측정용이다.

폴더 하나가 곡 하나다: `rock_slow_90`, `rock_fast_128`, `funk_108`, `soul_105`, `hiphop_87`. 이름의 숫자가 bpm이다. 각 폴더에 파일 5개가 있다.

| 파일 | 내용 |
| --- | --- |
| `drums.wav` | GMD 연주 소리 그대로. **드럼 정답** |
| `accomp.wav` | MUSDB train 곡에서 bass+other+vocals를 더한 60초 구간. 드럼 없는 반주. 청취·검산용이고 벤치마크의 정답 반주는 `mixture − drums`로 계산한다 |
| `mixture.wav` | 위 둘을 더한 것. 모델에 넣는 입력 |
| `onsets.csv` | GMD MIDI에서 뽑은 **타격 정답.** 시각(초), MIDI 피치, 악기 분류(kick·snare·hihat 등 9종), 세기 |
| `meta.yaml` | 어느 GMD 연주와 어느 MUSDB 곡 몇 초부터를 얼마 비율로 섞었는지. 출처·라이선스 |

반주가 MUSDB에서 왔으므로 합성곡도 교육·연구 목적 전용이다.

## 정리

평가 입력은 MUSDB test 50곡 + 합성곡 5곡 = 55곡이다. train 100곡과 GMD의 나머지 연주는 재료다. 두 묶음의 점수는 섞지 않고 따로 집계한다.
