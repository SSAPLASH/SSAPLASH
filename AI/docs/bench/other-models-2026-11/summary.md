# ADTOF 대체 채보 모델 학습 결과

측정일 2026-11-11 · 학습은 GPU 서버와 로컬 · 8패드 F1 ±50ms · 전체 표 `metrics.md` · MLflow 실험 `chart-other-models-finetune`

## 결론

- 질문은 "ADTOF 말고 MIT·Apache-2.0 채보 모델을 학습해서 지금 서비스 수준으로 올릴 수 있는가"였고, 답은 두 모델에서 그렇다이다
- STRUM의 CRNN 한 개(MIT)는 학습 뒤 평가 데이터 다섯 묶음 모두에서 지금 서비스보다 높다. 다만 ENST에서는 킥 규칙 하나를 붙여야 한다
- Inverse Drum Machine(Apache-2.0)은 GRU 크기를 128로 키운 구성이 규칙 없이 다섯 묶음 모두 지금 서비스 수준이다
- 두 모델의 점수를 평균하면 규칙 없이 다섯 묶음 모두 지금 서비스보다 높고, 같은 실제 곡으로 학습한 ADTOF 앙상블보다도 높다
- YourMT3+(Apache-2.0)와 ADT_STR(CC BY-SA 4.0)은 학습 뒤에도 실제 발매곡에서 서비스보다 0.02 ~ 0.04 낮다

## 데이터와 기준

- 학습 데이터 두 가지. 실제 발매곡 457곡 34.7시간은 Songsterr 탭을 원곡에 맞춘 정답이고 입력은 서비스 분리 모델로 뽑은 드럼이다. E-GMD 어쿠스틱 킷은 서버 학습 분할 21,294곡 206시간이다
- 학습은 모델마다 두 가지로 했다. 실제 곡만 쓴 것과, 구간의 30%나 50%를 E-GMD에서 뽑아 섞은 것이다
- 검증 10곡은 노트 시각 옮김과 패드별 문턱값을 고르는 데만 썼다. 학습 곡·검증 곡·평가 곡은 서로 겹치지 않는다
- 평가 데이터 다섯 묶음: 시험 31곡, 처음 보는 38곡, MDB 23곡, ENST 64곡 드럼 단독, ENST 64곡 원곡 분리. 앞의 둘이 실제 발매곡이다
- "지금 서비스 수준"의 기준: 실제 발매곡 두 묶음은 서비스 대비 차이의 95% 구간이 0을 포함하거나 그보다 위, MDB와 ENST 세 묶음은 차이가 −0.01 안
- 95% 구간은 곡을 2,000번 다시 뽑아 구했다

## 모델별로 확인한 것

STRUM

- 저장소의 전체 파이프라인이 아니라 그 안의 8종 온셋 CRNN 한 개만 떼어 학습했다. 파라미터 4,200만 개이고 드럼 킷 분리 모델을 쓰지 않는다
- 서비스보다 높은 패드는 라이드, 크래시, 하이햇, 탐 세 종류다. 시험 31곡에서 라이드 0.663 대 0.378, 플로어 탐 0.425 대 0.200. 킥과 스네어는 0.01 ~ 0.02 낮다
- E-GMD를 섞으면 MDB가 0.850에서 0.904로 오르고, 실제 발매곡 점수는 0.01 안에서 그대로다
- ENST 드러머 1은 킥이 탐으로 잡힌다. 킥 규칙은 탐이 킥보다 많이 잡힌 곡에서만 킥 점수를 키우고 겹친 탐을 지운다. ENST와 MDB를 보고 만든 규칙이라 그 두 데이터의 점수는 규칙에 유리하게 나왔을 수 있다
- 서비스보다 낮은 곳은 MDB의 미드·플로어 탐과 ENST 드러머 1의 스몰 탐이다. MDB는 탐 정답이 7곡에 90개뿐이다
- 채보 시간은 로컬 GPU에서 곡당 약 2초다

Inverse Drum Machine

- 원래 인코더는 파라미터 7.6만 개다. 여기에 양방향 GRU 가지를 더해 학습했다
- GRU 크기가 결과를 갈랐다. 64는 ENST에서 −0.012 ~ −0.045, 256은 MDB에서 −0.024로 기준 밖이고 128만 다섯 묶음을 채운다
- E-GMD를 섞기 전에는 MDB 0.806, ENST 0.772였다

YourMT3+

- 로컬 GPU 8GB에서만 학습했다. E-GMD를 섞으면 MDB 0.790 → 0.853, ENST 0.738 → 0.817로 오른다
- 스텝을 5,000에서 10,000으로 늘려도 다섯 묶음 모두 0.01 안에서 그대로다
- 실제 발매곡에서 낮은 패드는 하이햇과 라이드다. 시험 31곡 하이햇 정밀도 0.695, 재현율 0.669

ADT_STR

- 학습률 1e-4에서는 2,000 ~ 4,000스텝 뒤 검증 점수가 0.86에서 0.39까지 떨어졌다. 채보는 가장 높은 지점의 가중치로 했다
- 학습률을 3e-5, 1e-5로 낮춘 네 가지는 모두 처음 학습보다 낮다

## 채점 방식에서 고친 것

- 노트 시각 옮김 값을 ±50ms 점수로 고르면 −20ms처럼 정답과 어긋난 값이 뽑힐 수 있었다. ±50ms에서는 −20 ~ +20ms 사이 점수 차이가 0.005 안이기 때문이다. ±25ms 점수로 고르게 바꿨고 STRUM은 0ms, Inverse Drum Machine은 −5ms가 됐다
- 정답 시각이 실제 소리 시작점보다 얼마나 앞뒤인지는 데이터마다 다르다. 킥 기준으로 Songsterr는 7ms 앞, ENST는 6ms 앞, MDB는 4ms 뒤다

## 알아 둘 점

- 실제 발매곡 두 묶음은 학습 곡과 다른 곡이지만 정답이 같은 Songsterr 탭 방식이다. 탭이 적히는 방식을 배운 몫이 점수에 들어 있다
- 점수 평균 조합은 스몰 탐이 시험 31곡에서 0.000으로 사라진다. 검증 10곡에서 고른 스몰 탐 문턱값이 0.80으로 높게 잡혔다
- 학습한 가중치를 어디까지 배포할 수 있는지는 정해지지 않았다. 학습에 쓴 것은 Songsterr 탭, 시중 발매곡 음원, E-GMD다
- 서비스 워커에 넣어 채보를 만들어 보는 일은 이 작업 범위가 아니다
- 서버에서 학습한 가중치는 서버 `~/ssaplash/ext_ft/runs/`와 `~/ssaplash/ext_ft_r2/runs/`에 있다

## 저장소에 있는 코드

- 이 문서의 "지금 서비스"는 측정 때 비교 기준으로 둔 ADTOF + 드럼 킷 분리 모델(`adtof_drumsep.yaml`)이다. 이 측정 뒤 서비스 채보 모델은 표의 "STRUM, 실제 곡 + E-GMD + 킥 규칙"으로 바뀌었다
- STRUM의 학습과 채점 코드는 `scripts/train_ext/`에 있고 명령은 README "STRUM 채보 모델 학습" 절에 있다
- Inverse Drum Machine, YourMT3+, ADT_STR, 점수 평균 조합은 서비스에 쓰지 않아서 학습·채점 코드를 저장소에 넣지 않았다. 이 문서와 `metrics.md`의 해당 행은 측정 기록으로만 남긴다
