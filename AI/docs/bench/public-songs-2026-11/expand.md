# 공용 곡 늘리기와 실제 곡 학습 (11/08)

설계 `.claude/plans/CHART-003-songsterr-expand-train.md` · 로컬 RTX 4070 · 8패드 F1 ±50ms · ENST c1·c4는 라이드 · 괄호는 지금 서비스 대비 차이와 같은 곡끼리 2,000번 다시 뽑은 95% 구간

## 결론

- 지금 서비스보다 나은 방법을 찾았다. ADTOF 점수를 기본 가중치와 실제 곡 5종 학습 가중치로 각각 내어 킥·스네어·하이햇·심벌 열은 평균하고 탐 열은 기본 것을 쓴 뒤, 크래시·라이드 이름만 8패드 학습 가중치 것으로 바꾼다. 처음 보는 38곡 +0.025 (+0.016 ~ +0.036), 시험 31곡 +0.013, ENST +0.008·+0.013, MDB +0.022로 다섯 데이터 모두 오른다(9절)
- 비용은 ADTOF를 두 번 더 돌리는 것으로 곡당 GPU 약 1.5초다. 학습한 가중치 두 개(`data/models/songsterr_ft/five_all/last.pth`, `data/models/songsterr_ft/pads_all_noguard/last.pth`)를 서비스에 같이 실어야 한다
- 규칙 값·문턱값 바꾸기, 반복 마디 섞기, 크래시 뒤 라이드, 원곡 입력 섞기는 실제 곡에서 오르지 않았다(8절, 9.1). 바깥 모델(ADT_STR, STRUM, MVSEP 새 DrumSep)은 측정하지 않았다(9.2)

아래는 11/08 오전까지의 결론이다.

- Songsterr 인기곡 100곡을 더 받아 98곡을 정렬했고, 정렬 결과가 좋은 93곡을 학습 83곡·검증 10곡으로 썼다. 시험은 기존 31곡으로 고정
- 실제 곡으로 학습한 모델은 같은 종류의 검증 곡에서는 크게 올랐지만(5종 F1 0.852 → 0.883), 시험 31곡에서는 지금 서비스와 비슷하거나 낮고(−0.003 ~ −0.028), ENST에서는 떨어졌다(−0.03 ~ −0.06). ENST에서 무너지는 곳은 드러머 1(−0.07 ~ −0.13)이고 드러머 2·3은 ±0.01 안이다. 11/07 E-GMD 학습과 같은 모양이다
- 학습 곡 수를 25 → 50 → 83곡으로 늘려도 시험 31곡 점수는 −0.012 → −0.009 → −0.003으로 조금 나아질 뿐 지금 서비스를 넘지 않았다
- 8패드 출력 학습은 이름 붙이기를 크게 올렸다. 시험 31곡 라이드 0.378 → 0.574, 크래시 0.679 → 0.735, 탐 3종 0.190 → 0.313. 대신 킥이 떨어지고 MDB 탐 3종이 0.671 → 0.157로 무너져 전체는 낮다
- 모든 데이터에서 떨어지지 않은 것은 학습 없이 문턱값만 바꾼 두 설정이다. 새 곡 검증 10곡으로 맞춘 문턱값(킥 0.22·스네어 0.18·하이햇 0.18·심벌 0.26)은 시험 31곡 +0.002, ENST +0.005·+0.010, MDB +0.001. 11/08 오전에 MDB로 고른 0.85배(0.187·0.204·0.187·0.30)와 크기가 비슷하다
- 탐 거르기 수정(11/08 기존 31곡으로 고름)은 새 93곡에서 −0.001로 오르지 않았다. 기존 31곡에서 오른 것은 고른 데이터라서였다

## 1. 데이터

- Songsterr 곡 목록 API(`api/songs`) 500곡 중 드럼 트랙 조회수 순, 기존 31곡 제외 상위 100곡. 탭·마디 시각·대표 유튜브 음원을 받음(`data/songsterr/expand_songs.py`, 받은 목록 `data/songsterr/data/expand/picked.jsonl`)
- 분리 실패 2곡(Free Bird·Pneuma, 9분 넘는 곡), 정렬 결과로 뺀 5곡(마디를 실제 박에 붙인 비율 0.85 미만 4곡, 노트 300개 미만 1곡). 학습 83곡·검증 10곡(`scripts/make_songsterr_splits.py`, 곡 이름 해시 순서)
- 새 곡 정답 시각은 13.7ms 보정이 들어간 `align_song.py`로 만듦. 서비스 예측과의 시각 차이 중앙값 −1.3ms
- 데이터셋 로더 `kind: songsterr`(`src/ssaplash_ai/bench/datasets/songsterr.py`): 분리 드럼·드럼리스 MR·채보 JSON. 학습 입력은 서비스 분리 모델이 뽑은 드럼

## 2. 학습

- 설정 `configs/train/songsterr_{five_25,five_50,five_all,pads_all_noguard}.yaml`: 기본 ADTOF에서 시작, 에폭 6 × 1,000스텝, 배치 32, 학습률 1e-4, 곡을 읽을 때 창 64개, 고르기 지표 5종 F1. 8패드 출력은 5종 기준 안전장치에 걸려 3에폭에 멈춰서 안전장치를 끄고 다시 학습함
- 학습 시간(학습 기록 기준): 83곡 54분(특징 만들기와 GPU를 같이 씀), 50곡 28분, 25곡 26분, 8패드 27분(평가와 GPU를 같이 씀)

| 문턱값 낮춤 + 심벌만 8패드 모델 (검증으로 고른 것) | 0.735 / 0.574 | 0.687 / 0.782 | 0.587 / 0.734 | 0.737 / 0.777 |
| 문턱값 낮춤 + 심벌 이름만 8패드 모델 | 0.714 / 0.486 | 0.660 / 0.809 | 0.575 / 0.767 | 0.709 / 0.841 |

- 고른 조합은 시험 31곡에서 지금까지 가장 높다(0.788, +0.010). 라이드 0.378 → 0.574, 크래시 0.679 → 0.735. 대신 ENST 라이드가 0.819 → 0.782로 떨어져 ENST에서는 문턱값 낮춤 하나보다 덜 오르고(+0.002·+0.006), MDB는 −0.003
- "심벌 이름만 바꾸기"는 네 데이터 모두 올랐지만(+0.004 ~ +0.009) 검증에서는 2위였다. 시험 결과를 보고 고르면 시험 곡으로 고르는 것이 되므로, 따로 떼어 둔 곡으로 한 번 더 확인해야 한다
- 서비스에 넣으려면 채보 워커가 ADTOF를 두 번(기본 가중치, 8패드 가중치) 돌려야 한다. 걸리는 시간은 9.3

## 8. 규칙·문턱값으로 더 올릴 여지 (11/08)

지금 서비스(ADTOF 5종 + DrumSep + 규칙)에서 규칙 값과 문턱값을 바꿔 실제 곡 점수가 오르는지 확인했다. 고르기는 새 93곡(검증 10 + 학습 83, 규칙은 학습하지 않으므로 고르기에 씀), 확인은 시험 31곡·ENST·MDB. 스크립트 `scripts/postproc_eval.py`(후보 `k2t`·`thr_abs` 추가), 결과 `data/results/tom_naming/`.

새 93곡 8패드 F1 0.821 기준, 지금 서비스 대비 차이

| 바꾼 것 | 범위 | 차이 |
| --- | --- | --- |
| 탐 묶음 최소 틈(반음) | 2 · 4 · 5 · 6 (지금 3) | −0.003 ~ −0.001 |
| 탐 묶음 최소 비율 | 0.05 ~ 0.2 (지금 0) | −0.000 ~ +0.001 |
| 탐 묶음 수·이름 짓기 | 2 · 4개, bands·order (지금 3개, hybrid) | −0.002 ~ 0.000 |
| 킥·스네어·하이햇·심벌 문턱값 하나씩 | 0.12 ~ 0.38 | −0.004 ~ +0.001 |
| 탐 문턱값 | 0.20 · 0.26 · 0.38 · 0.44 (지금 0.32) | −0.003 ~ +0.001 |
| 크래시 가중치·심벌 구간 | 0.4 ~ 1.0, 40 ~ 120ms (지금 0.7, 80ms) | −0.003 ~ +0.000 |

- 모든 값이 지금 값 ±0.001 안이다. 지금 규칙 값과 문턱값이 실제 곡에서도 이미 가장 좋은 자리에 있다
- 새 곡 검증 10곡으로 맞춘 문턱값(탐 0.26 등)은 새 93곡에서 −0.002, 시험 31곡에서 +0.001이다. 실제 곡에서는 오르지 않고, ENST에서만 오른다(+0.004·+0.007)

| --- | --- | --- | --- | --- |

- 하이햇: 정답에 페달 하이햇(탭 44번)이 하이햇으로 합쳐져 있지만 정답 하이햇의 5%(새 93곡)·10%(시험 31곡)뿐이다. 페달을 빼도 하이햇 F1이 +0.015·+0.017만 오른다. 페달 아닌 하이햇도 15~18%를 놓친다
- 하이햇으로 찍힌 라이드·크래시를 DrumSep 트랙 에너지 비로 바꾸는 규칙은 6만 타격 중 순이득이 80개 정도라 넣지 않았다
- 탐 이름: 시각이 맞은 탐 중 이름까지 맞은 비율이 시험 31곡 37%, 새 93곡 53%다. 곡마다 높낮이 순서를 지키면서 이름을 가장 잘 바꿔 붙이면 78%·77%가 된다. 높낮이 순서는 대체로 맞고, 몇 종류로 나눠 어떤 이름을 붙이느냐에서 틀린다
- 정답 탭은 탐이 2종인 곡에서 스몰·플로어, 미드·플로어, 스몰·미드를 곡마다 다르게 쓴다(새 93곡 8·10·6곡). 모든 곡에 같은 이름 바꾸기를 적용하면 새 93곡에서 지금보다 오르는 것이 없다. 곡마다 이름을 완벽하게 붙였을 때의 최대치는 8패드 F1 +0.011(새 93곡)·+0.014(시험 31곡)이다
- 놓친 탐 중 킥으로 찍힌 것(새 93곡 971개)은 DrumSep 탐 트랙이 킥 트랙보다 훨씬 크다. 킥을 탐으로 바꾸는 규칙(`k2t`)은 새 93곡 +0.003이었으나 시험 31곡 −0.001, ENST 드러머 1 −0.06(킥을 탐으로 바꿈)이라 넣지 않았다
- ADTOF 탐 점수가 낮은 피크를 탐 트랙 비중으로 되살리는 규칙은 맞는 비율이 55% 정도라 올릴 수 있는 폭이 작아 시험하지 않았다

```bash
uv run python scripts/public_songs_eval.py features --songs data/songsterr --out data/rule_features/public_songs
# 규칙·문턱값 후보 채점 (8절, 9.3)
uv run python scripts/postproc_eval.py run --dataset configs/bench/datasets/public_songs_holdout38.yaml --candidates docs/bench/public-songs-2026-11/candidates_check.json --workers 8 --out data/results/tom_naming/holdout38_check.csv
# 점수 평균 조합 채점 (9.1, 9.3)
F=data/models/songsterr_ft/five_all/last.pth
P=data/models/songsterr_ft/pads_all_noguard/last.pth
uv run python scripts/ensemble_eval.py --dataset configs/bench/datasets/public_songs_holdout38.yaml --pads $P --cand base=default@drums --cand avg_five_notom=default@drums,$F@drums:kshc --out data/results/ensemble/holdout38.csv
```

- `ensemble_eval.py`의 후보는 `이름=가중치@입력:열`이다. 가중치 `default`는 서비스 기본 ADTOF, 열 글자 `ksthc`는 킥·스네어·탐·하이햇·심벌 점수 열이다. `--pads`를 주면 후보마다 크래시·라이드 이름을 8패드 모델 것으로 바꾼 `+cym_name` 줄과 심벌 타격을 통째로 바꾼 `+cym_take` 줄이 같이 나온다
- 결과 csv는 곡마다 패드별 맞힘·잘못 적음·빠뜨림 개수다. 첫 후보 대비 차이와 95% 구간은 `scripts/postproc_eval.py`의 `f1_of`·`bootstrap`으로 낸다
