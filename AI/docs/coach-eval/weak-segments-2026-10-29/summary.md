# 약점 분석 합성 평가 (2026-10-29, S15P31A307-139)

약점 구간 분석 규칙(`analyzerVersion` `weak-rules-0.1`, 9개 `pattern`)을 **가짜 플레이 로그**로 검증한 결과다.
숫자 표는 [results.md](results.md), 강도별 탐지율 그림은 [sensitivity.png](sensitivity.png), 예시 요청·응답은 [samples/](samples/)에 있다.

**이 평가가 말해 주는 것과 아닌 것.** 실제 사용자 로그가 없어서 연주를 모델로 만들었다. 이 결과는 "규칙이 설계한 대로 움직이는가, 임계값 근처에서 어떻게 변하는가"를 보여 준다.
"실제 사용자의 약점을 이만큼 잘 찾는다"는 근거가 아니다. 한계는 맨 아래에 있다.

## 1. 한눈에 보기

| 질문 | 답 |
| --- | --- |
| 규칙이 설계대로 움직이는가 | 대체로 그렇다. 전체 늦음·빠름, 한쪽 손, 전환, 구간 놓침은 임계값 부근에서 탐지율이 0에서 100%로 바뀐다 |
| 약점이 강하면 잘 찾는가 | 강한 강도에서 `TIMING_*`·`HAND_WEAK`·`TRANSITION_*`·`MISS_CLUSTER`는 99~100%다. `PAD_*`(77·85%)와 `UNSTEADY`(68%)는 가이드 90%에 못 미친다 |
| 정상 로그에서 잘못 찾는가 | 전체 5%(3~8)다. 숙련 0%, 평균 3%, **초보 12%**이고 전부 `MISS_CLUSTER`다. 초보가 가이드 5%를 넘는다 |
| `goodMs`가 달라도 같은가 | 같은 강도(× `goodMs`)에서 30~150ms 사이에 뚜렷한 경향이 없다. 비례 설계가 동작하는 쪽이다 |
| 한 약점이 다른 패턴을 끌고 오는가 | 그렇다. 중복 줄이기 규칙에 빈틈이 있다(3.2) |
| 응답 시간 | 5,047건 분석 0.028초, 48,464건 0.065초(검증 포함해도 0.3초 안팎). 목표(1초, 3초)보다 한참 빠르다 |

가이드(설계 문서 U1)는 "강한 강도 탐지율 90% 이상, 정상 오탐 5% 이하"이고 미달이어도 완료를 막지 않는다. 미달 항목은 원인과 조정안을 아래에 적었다.

## 2. 방법

- **채보:** 노트를 400ms 간격으로 놓은 합성 채보. 패드 배치 3종(`rock`, `mixed`, 8패드 균등)과 무작위 배치(`random`). 패드 약점 시나리오는 `random`을 쓴다(주기 배치에서는 스네어 앞에 늘 하이햇이 와서 패드 약점과 전환 약점을 구분할 수 없었다).
- **연주 모델:** 노트마다 오차를 정규분포로 뽑는다(평균·표준편차는 `goodMs`의 비율). 판정은 FE 규칙을 따라 오차 25ms 이하 PERFECT, `goodMs` 이하 GOOD, 그 밖이면 노트 MISS와 여분의 타격으로 기록한다. 무작위 놓침(1~8%)과 여분 타격(1~4%)도 넣는다.
- **심는 약점 9종 × 강도 4단계:** 평균 오차, 패드 오차, 전환 직후 오차·놓침, 약한 손 세기, 구간 놓침, 오차 폭. 강도는 임계값 아래·근처·위를 지나도록 정했고 임계값을 코드에서 읽지 않는다(순환 검증 방지).
- **정상 3단계:** 숙련·평균·초보(오차 폭 0.12·0.25·0.35 × `goodMs`, 놓침 1·4·8%).
- **규모:** 칸마다 100번, 총 3,900번. 노트 수(60·200·600)와 `goodMs`(30·50·60·100·150)는 번갈아 쓴다. 시드는 고정이라 같은 명령이면 같은 결과다.
- **정답 판정:** 기대 `pattern`이 응답에 있으면 탐지. 구간형은 겹침(교집합 ÷ 합집합) 0.5 이상이면 위치 일치. 기대 패드를 `pads[]`가 포함하면 패드 일치. 정상 로그에서 약점이 하나라도 나오면 오탐.

## 3. 결과와 해석

### 3.1 탐지율: 임계값 근처에서 의도대로 바뀐다

| 패턴 | 설계 임계값(`goodMs` 비) | 탐지율이 바뀐 곳 |
| --- | --- | --- |
| `TIMING_LATE/EARLY` | 평균 오차 0.3 | 강도 0.25는 0~1%, 0.4는 100% |
| `HAND_WEAK` | 세기 비율 0.75 미만 | 0.8은 0%, 0.7은 100% |
| `TRANSITION_LATE` | 평균 오차 0.5 | 0.3은 0%, 0.5는 45%, 0.7은 100% |
| `TRANSITION_MISS` | 놓침 30% | 0.2는 7%, 0.35는 77%, 0.5는 97% |
| `MISS_CLUSTER` | 창 놓침 40% | 0.2는 11%, 0.4는 64%, 0.6은 99% |
| `PAD_LATE/EARLY` | 평균 오차 0.4 | 0.25는 0%, 0.4는 55·47%, 0.6은 96·95% |

- 위치·패드 일치는 높다. `TRANSITION_*`는 위치·패드 모두 100%, `MISS_CLUSTER` 위치는 0.4 이상에서 98~100%(0.2에서는 73%, 8/11), `PAD_*`의 패드는 100%다.
- 강도가 임계값 근처(경계)일 때 탐지율이 50% 안팎인 것은 정상이다. 임계값의 위치가 설계대로라는 뜻이다.

### 3.2 교차 반응: 한 약점이 다른 패턴을 끌고 온다

| 심은 약점 | 함께 나온 것 | 해석 |
| --- | --- | --- |
| 전체 늦음 0.6 | `TRANSITION_LATE` 100/100 | 모든 노트가 늦으니 모든 전환 직후 노트도 늦다 |
| 스네어만 늦음 0.6·0.9 | `TRANSITION_LATE` 72/100 | 스네어로 들어오는 전환(A→스네어)이 전부 늦게 잡힌다 |
| 전환에서 늦음 1.0 | `TRANSITION_MISS` 99/100 | 큰 지연은 판정 폭 밖으로 밀려 놓침으로 기록된다 |
| 오차 폭 0.75 | `MISS_CLUSTER` 82/100 | 폭이 크면 놓침이 늘고 그중 일부가 몰려 보인다 |

설계의 중복 줄이기 규칙에는 "`TIMING_*`가 있으면 같은 방향 `PAD_*` 기준을 높인다" 등이 있지만 **`TRANSITION_LATE`와 `TIMING_*`·`PAD_*`의 관계는 없다.** 같은 원인이 여러 약점으로 나뉘어 나오는 것이 위 표다.

### 3.3 선택 단계에서 원인이 밀린다

노트 600개에서 `PAD_LATE` 강도 0.9의 탐지율이 26/33(79%)이다(200개는 33/33). 별도로 확인한 결과, 못 찾은 경우 모두 선택 전에는 `PAD_LATE` 후보가 있었고 `TRANSITION_*`·`MISS_CLUSTER` 후보에 밀려 "최대 5개, 같은 패턴 2개까지" 선택에서 빠졌다.
이 확인은 진단용 임시 스크립트로 했고 저장소에는 없다. 같은 원인(스네어가 늦음)이 전환 후보 여러 개로 나뉘어 심한 정도 순위를 차지한다.

### 3.4 노트 수가 적으면 조건을 못 채운다

노트 60개에서 `PAD_LATE` 강도 0.9가 18/34(53%), 200개에서는 33/33이다. 지연이 크면 유효 타격이 놓침으로 빠져서 "패드당 유효 타격 8개 이상" 조건을 못 채우는 것으로 **추정**한다(직접 확인하지는 않았다). `TRANSITION_MISS` 0.2도 60개에서 5/34, 600개에서 0/33이다.

### 3.5 `UNSTEADY`: 판정 폭에 잘려 거의 안 잡힌다

오차 폭 0.55 이하는 거의 0%, 0.75에서 68%다. 판정 폭(±`goodMs`) 밖은 놓침으로 빠지므로 남은 타격의 관측 표준편차가 작아진다.
정규분포를 ±1(× `goodMs`)로 자른 표준편차를 계산하면 입력 0.55는 약 0.46, 0.75는 약 0.51이다(분석 계산, 규칙 임계값은 0.5). 임계값 0.5를 넘으려면 입력이 0.7 이상이어야 하고, 그때는 놓침이 15% 안팎이라 `MISS_CLUSTER`가 같이 나온다.

### 3.6 정상 로그의 오탐은 초보에서 생긴다

| 숙련도 | 오탐률 (95% 구간) | 나온 pattern |
| --- | --- | --- |
| 숙련 | 0% (0–4) | — |
| 평균 | 3% (1–8) | `MISS_CLUSTER` 3/100 |
| 초보 | 12% (7–20) | `MISS_CLUSTER` 12/100 |
| 합계 | 5% (3–8) | |

초보 모델은 무작위로 8% 놓친다. 5초 창에 노트가 약 12개이고 40% 이상 놓침이면 걸리는데, 기본 놓침률이 높은 사람은 우연히 한 창에 몰리기 쉽다. 실제 초보자는 이보다 더 많이 놓칠 수 있어서 실제 오탐은 더 높을 가능성이 있다.

### 3.7 `goodMs` 비례

같은 강도(× `goodMs`)에서 30·50·60·100·150ms 사이의 탐지 횟수 차이는 대체로 20회 중 ±5회 안이다. 이 크기는 표본 잡음 범위다(95% 구간 폭이 ±20%p 안팎).
한 가지 눈에 띄는 것은 `MISS_CLUSTER` 0.4가 150ms에서 9/20이고 다른 `goodMs`에서 12~15/20인 점이다. 잡음일 수 있지만 표본을 늘려 다시 확인할 만하다.

### 3.8 응답 시간과 서버 경유

| 타격 행 수 | 검증(초) | 분석(초) |
| --- | --- | --- |
| 5,047 | 0.044 | 0.028 |
| 48,464 | 0.232 | 0.065 |

시간은 측정할 때마다 조금씩 달라진다(반복 3회 중 최솟값). 샘플 6건을 서버 처리 함수(`process_body`)에 JSON으로 넣은 결과가 `analyze()` 직접 호출과 모두 같았다. HTTP 라우팅·네트워크는 포함하지 않는다(윈도우에서 `TestClient`가 간헐 실패해 함수 단위로 확인).

## 4. 조정안 (적용하지 않음)

설계 결정(U2)대로 이 작업에서는 임계값·규칙을 바꾸지 않았다. 아래는 승인 뒤 별도 작업에서 적용하고, 같은 명령으로 다시 평가해 비교할 후보다. 효과는 가설이며 재평가로 확인해야 한다.

| # | 대상 | 변경 후보 | 근거 | 기대 효과 | 위험 |
| --- | --- | --- | --- | --- | --- |
| A1 | `MISS_CLUSTER` 오탐 | 창 놓침률이 **곡 전체 놓침률보다 일정 폭(예: +25%p) 이상 높을 때만** 인정 | 초보 오탐 12%(3.6). 기본 놓침률이 높은 사람은 창 놓침률 40%를 우연히 넘는다 | 초보 오탐 감소 | 실제로 계속 놓치는 사람의 약점을 안 잡는다(이 경우는 전체 놓침 자체가 문제) |
| A2 | `TRANSITION_LATE` 중복 | `TIMING_*`가 있으면 전환 평균이 전체 평균보다 일정 폭(예: 12ms) 더 늦을 때만. `PAD_LATE`가 있으면 그 패드로 들어오는 전환은 뺀다 | 교차 반응 3.2 | 같은 원인이 여러 약점으로 나뉘는 것을 줄임 | 전환 약점이 패드 약점에 가려질 수 있음 |
| A3 | 선택 단계 | 같은 원인 후보를 합친 뒤 선택, 또는 같은 패드를 가리키는 후보는 `PAD_*`가 앞서도록 | 3.3 | 600노트에서 `PAD_*`가 밀리지 않음 | 순위 규칙이 복잡해진다 |
| A4 | `UNSTEADY` 임계값 | 표준편차 임계 0.5 → 0.4(× `goodMs`)와 `severity` 분모 조정 | 3.5. 0.4면 입력 0.5(관측 약 0.44)부터 잡힘 | 판정 폭에 잘린 박자 불안정도 잡힘 | 정상(초보 입력 0.35, 관측 약 0.33)에 가까워 오탐 증가 가능. 평가에서 확인 필요 |
| A5 | 패드당 최소 유효 타격 | 노트가 적은 곡에서 지연이 큰 패드가 조건에서 빠지지 않도록 놓침을 함께 세는 방안 | 3.4(추정) | 짧은 곡의 패드 약점 탐지 | 놓침 계열과 역할이 겹친다 |

제안 순서는 A1, A2, A3(오탐·중복이 사용자에게 직접 보이는 것), 그다음 A4, A5다. 모두 `coach/config.py`와 후보 선택 코드를 건드리므로 `analyzerVersion`을 올려야 한다(BE의 `generator_version`에 기록됨).

## 5. 한계

- 합성 분포는 실제 사용자와 다르다. 이 평가는 규칙이 설계대로 동작함을 보일 뿐 정확도를 주장하지 않는다.
- 연주 모델이 정규분포 중심이라 손 떨림, 곡별 습관 같은 실제 패턴을 반영하지 못한다.
- 판정 폭에 갇힌 오차는 평균·표준편차를 작게 만든다(3.5). 큰 오차를 심어도 늦음·불안정 패턴이 약하게 보이고 놓침 계열이 이를 보완한다.
- 정상 로그에서 오탐이 적어도 약점이 있는 실제 사용자를 잘 찾는다는 뜻은 아니다. 정상 3단계 숙련도와 연주 모델 기본값은 가정값이다.
- 키보드 입력(`stickId`가 null)에서는 `HAND_WEAK`을 평가하지 않았다.
- 꺼 둔 패턴 4종(`TEMPO_DRIFT_*`, `VELOCITY_FADE`, `PAD_CONFUSION`, `DENSE_WEAK`)은 평가하지 않았다. 켤 때 시나리오를 추가한다.
- 칸마다 시험이 100번(`goodMs`·노트 수로 나누면 20~34번)이라 작은 차이는 잡음이다.
- 3.3의 선택 단계 확인과 3.4의 원인은 임시 진단·추정이며 이 저장소의 도구로 재현되는 표는 노트 수별 탐지율(results.md 3절)까지다.

## 6. 다시 돌리는 법과 기록

```bash
uv run python -m ssaplash_ai.coach_eval.cli --out docs/coach-eval/weak-segments-2026-10-29 --mlflow
```

- 결과 표·집계·그림·예시 데이터를 `--out` 폴더에 쓴다. 규칙·임계값을 바꾼 뒤에는 날짜 폴더를 새로 만들어 같은 명령으로 비교한다.
- MLflow 실험 이름은 `coach-weak-segments-eval`이고 run 이름은 `--out` 폴더 이름이다. 지표 이름은 `recall/{시나리오}/{강도}`, `fpRate/{숙련도}`, `analyzeSec/hits{행 수}`다. 기본 기록 위치는 로컬 `mlruns/`이고(git 미추적), 팀 MLflow 서버에 올리려면 SSH 터널을 연 뒤 `--tracking-uri`나 `MLFLOW_TRACKING_URI`를 지정한다.
- 시험은 `uv run pytest tests/coach_eval`이다. 생성기가 만든 요청이 BE 형식 검증을 통과하는지, 같은 시드가 같은 결과를 내는지, 지표 계산이 맞는지를 확인한다.
