# 파트 간 협업 요청·회신 문서 (mail)

파트 간 작업 요청과 회신을 한 형식으로 통일한다. 문서는 git으로 관리하지 않고 팀원 간 직접 전달한다.

## 저장 위치

- 모든 문서는 저장소 루트의 `.claude/mail/` 에 둔다. 이 폴더는 `.gitignore` 대상이다.
- 다른 곳에 만들지 않는다. 받은 문서도 이 폴더에 넣고 처리한다.

## 언제 쓰는가

- **다른 파트의 작업을 막는 결정이나 요청**만 문서로 쓴다. 예: API 스펙, 데이터 포맷, 인터페이스 합의, 선행 작업 요청.
- 단순 질문·확인은 문서를 만들지 않고 Jira 댓글이나 메신저로 처리하라고 사용자에게 안내한다.
- 같은 건에 대한 추가 논의는 새 문서를 만들지 않고 기존 문서의 회신으로 이어 쓴다.

## 파일명

```
{스토리 코드}_{업무내용}_from_{요청자}.md
예) AUTH-001_소셜로그인-토큰-포맷_from_최형수.md
```

- **스토리 코드:** 관련 Jira 스토리 코드(`{에픽 prefix}-{3자리 번호}`, 영문 대문자)를 쓴다. Jira 키(`S15P31A307-*`)를 쓰지 않는다.
- 관련 스토리가 없는 지원 업무는 공식 업무 분류(`PLAN`, `UX`, `DESIGN`, `TECH`, `INFRA`, `DOCS`, `QA`, `PT`)를 쓴다. 예: `INFRA_배포서버-포트-개방_from_최형수.md`
- **업무내용:** 한글 가능, 공백 대신 `-`, 15자 안팎.
- **요청자:** 처음 문서를 만든 사람. 회신 후에도 파일명은 바꾸지 않는다.
- 스토리 코드나 요청자를 모르면 추측하지 말고 사용자에게 묻는다.

## 새 요청 작성

1. 같은 폴더의 [template.md](template.md)를 읽고 절 순서와 frontmatter 필드를 그대로 지킨다. 절을 추가·삭제하지 않는다.
2. frontmatter:
   - `status`: `요청`으로 시작한다.
   - `from` / `to`: `FE`, `BE`, `AI`, `EMB`, `Infra` 중 하나.
   - `jira`: **요청자 본인이 이 요청을 진행하는 Jira 작업(Task) 키**. 스토리·에픽 키로 대체하지 않는다. 모르면 사용자에게 묻는다.
3. **핵심 요약:** 사람이 읽는 절이다. 5줄 이내, 배경 설명을 길게 쓰지 않는다.
4. **에이전트 지시사항:** 받는 쪽 에이전트가 이 문서만 보고 작업할 수 있게 쓴다. 파일 경로, 필드명, 예시 값처럼 구체적인 정보를 넣는다.
5. `## 회신` 이하는 템플릿 그대로 비워 둔다.
6. 작성 후 파일 경로를 사용자에게 알리고, 상대 담당자에게 전달하라고 안내한다.

## 회신 작성

1. `.claude/mail/` 에서 해당 문서를 찾아 전체를 읽는다.
2. **`## 회신` 위의 본문은 수정하지 않는다.** 회신 절만 채운다.
3. 회신 절에 회신자 이름과 **회신자 본인의 Jira 작업 키**를 적는다.
4. 에이전트 지시사항의 "회신 형식"이 요구한 항목을 빠짐없이 답한다.
5. frontmatter `status`를 갱신한다:
   - `회신완료`: 답변을 작성함
   - `합의`: 양쪽이 결론에 동의함
   - `폐기`: 요청이 취소됨
6. 재회신은 기존 회신 아래에 `## 회신 2`, `## 회신 3` 으로 이어 붙인다. 이전 회신은 수정하지 않는다.

## 받은 요청 확인

사용자가 "온 요청 확인" 등을 요청하면 `.claude/mail/` 의 문서 중 `to`가 사용자 파트이고 `status`가 `요청`인 문서를 목록으로 보여준다. 각 문서는 핵심 요약만 짧게 인용한다.

## 노션 기록 — 규약 한 줄

메일을 쓰거나 회신한 뒤, 노션 `Features` DB에서 스토리 코드와 `ID`가 같은 문서를 열어 `✉️ 협업 메일 (mail)` 절에 **규약을 한 줄씩** 적는다. 스토리 코드가 없는 메일(`PLAN`, `INFRA` 등)은 가장 관련 있는 에픽 문서에 적는다.

```
- [합의] refresh 토큰은 HttpOnly 쿠키, access 토큰은 응답 본문 — `ACCT-001_소셜로그인-결정-전달_from_최형수.md`
- [제안] HIT 패킷 14바이트, timestamp는 피크 순간의 센서 시각 — `PLAY-002_스틱-통신-프로토콜-제안_from_최형수.md`
- [미결] 패드 판별 위치 FE vs 스틱 — `PLAY-002_스틱-통신-프로토콜-제안_from_최형수.md`
```

**형식**

```
- [태그] 규약 — `파일명`
```

| 태그 | 뜻 |
| --- | --- |
| `[제안]` | 한쪽이 제시했고 아직 답이 없다 |
| `[합의]` | 양쪽이 동의했다. 이대로 구현한다 |
| `[미결]` | 답이 필요한데 아직 정해지지 않았다 |

**규칙 네 가지**

1. **한 줄 = 규약 하나.** 메일 하나에 결정이 셋이면 세 줄. 메일을 열지 않아도 무엇을 지켜야 하는지 보여야 한다.
2. **"~한다", "~이다"로 끝낸다.** "요청함", "전달함" 같은 행위 서술은 쓰지 않는다. 주어는 사람이 아니라 규약 대상(토큰, 패킷, URL…)이다.
3. **줄은 고쳐 쓴다, 쌓지 않는다.** 회신으로 합의되면 `[제안]`을 `[합의]`로 바꾸고, 내용이 바뀌면 그 줄을 고친다. 이력은 메일 파일에 있으니 여기엔 **현재 규약만** 남긴다.
4. **파일명은 그대로, 백틱으로 감싼다.** `.claude/mail/`의 파일명을 한 글자도 바꾸지 않고 끝에 붙인다. 노션이 `.md`를 링크로 바꾸므로 인라인 코드로 쓴다. 사람도 에이전트도 이 문자열로 근거를 찾는다.

**읽는 법**

- 내 스토리 문서의 메일 절 = 그 스토리의 파트 간 계약서. 구현 전에 `[합의]` 줄을 먼저 본다.
- `[미결]`이 있으면 메일 파일을 열어 회신한다.
- 에이전트는 작업 시작 전 이 절을 읽고, 메일을 쓰거나 회신한 직후 이 절을 갱신한다.
